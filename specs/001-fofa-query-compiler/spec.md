# Feature Specification: FOFA Natural-Language Query Compiler

**Feature Branch**: `001-fofa-query-compiler`

**Created**: 2026-09-24

**Status**: Draft

**Input**: User description: "定义一个系统，读取‘题目’目录中的竞赛题包，将自然语言资产搜索需求转换为准确的 FOFA Query，并完成校验、人工复核和合规答卷导出。"

## Clarifications

### Session 2026-09-24

- Q: 查询准确率验收时，应采用哪一种判定标准，才算一道题转换正确？ → A: 采用语义全通过制；字段、匹配方式、值、逻辑关系、否定和边界等原子约束必须全部正确，并由两名独立复核者解决分歧。
- Q: 正式答卷导出前，哪些答案必须经过人工确认？ → A: 全部题目必须逐题人工确认；高风险题还必须核对来源证据和风险检查项。
- Q: 当题目要求查阅外部资料，但原始页面暂时无法访问时，系统应如何处理该题？ → A: 将该题保持为阻塞状态；找到可核验的官方替代来源、可验证存档或用户提供的可核验材料后再继续，证据补齐前不得确认或导出。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导入并核验参赛包 (Priority: P1)

作为参赛者，我希望导入题目、参赛包信息和答案模板，并在开始作答前发现文件损坏、题号不一致或模板错误，避免整份答卷因结构问题被拒绝。

**Why this priority**: 如果题目集合或模板不完整，后续生成的所有答案都无法形成有效提交，是整个流程的基础门槛。

**Independent Test**: 分别导入一套完整参赛包以及包含缺题、重复题号、未知题号、无效 JSON 的异常包，确认系统只接受结构一致的完整参赛包，并为每项错误指出位置和原因。

**Acceptance Scenarios**:

1. **Given** 题目、参赛包信息和答案模板均有效且题号集合一致，**When** 用户导入参赛包，**Then** 系统显示包编号、题目总数和校验成功结果，并允许进入生成流程。
2. **Given** 答案模板存在缺失、重复或未知题号，**When** 用户导入参赛包，**Then** 系统拒绝开始生成，并列出所有不一致题号。
3. **Given** 任一输入文件不是合法的目标格式，**When** 用户导入参赛包，**Then** 系统不修改原文件，并提供可定位到文件和数据项的错误信息。

---

### User Story 2 - 生成可执行的 FOFA 查询 (Priority: P1)

作为参赛者，我希望系统逐题理解自然语言中的字段、匹配方式、逻辑关系、范围和约束，生成唯一且完整的 FOFA Query，从而高质量完成可直接转换的题目。

**Why this priority**: 查询语义准确性直接决定比赛得分，是系统的核心价值。

**Independent Test**: 使用覆盖基础字段、地理范围、协议、产品、证书、时间、正则、哈希、嵌套布尔逻辑和其他搜索语法迁移的已审阅样例，逐项比较生成结果与预期语义。

**Acceptance Scenarios**:

1. **Given** 一个可由单个 FOFA 条件表达的自然语言需求，**When** 用户生成答案，**Then** 系统输出一条不含解释文字的完整查询。
2. **Given** 一个包含 AND、OR、排除条件和嵌套优先级的需求，**When** 用户生成答案，**Then** 输出查询保留全部条件及原始逻辑优先级。
3. **Given** 一个包含原样文本、引号、反斜杠、正则或时间边界的需求，**When** 用户生成答案，**Then** 输出值被正确保留和转义，不改变搜索含义。
4. **Given** 一个从 Shodan、Google Dork、Hunter、Censys 或 urlscan.io 描述迁移的需求，**When** 用户生成答案，**Then** 输出只使用 FOFA 可表达的等价语义；无法等价表达时进入不可转换流程。

---

### User Story 3 - 安全拒绝不可转换需求 (Priority: P1)

作为参赛者，我希望系统识别非法输入、逻辑矛盾、主观描述、运行时遥测和 FOFA 不具备的数据能力，并使用比赛规定的固定答案，避免提交编造的查询。

**Why this priority**: 错误地生成一个看似合理的查询会造成确定性失分；可靠拒绝与正确生成同等重要。

**Independent Test**: 输入非法端口、非法 IP、互相矛盾的条件、主观指标和需要内部运行时数据的需求，确认每题只输出规定的固定拒绝文本。

**Acceptance Scenarios**:

1. **Given** 端口、IP、网段、时间或指纹值不合法，**When** 系统处理题目，**Then** 输出 `该需求不能直接转换为FOFA搜索语句`。
2. **Given** 同一资产必须同时满足互相排斥的条件，**When** 系统处理题目，**Then** 输出固定拒绝文本，而不是生成恒假或删减条件的查询。
3. **Given** 需求依赖 FOFA 不提供的实时内部指标、主观判断或未给出的事实，**When** 系统处理题目，**Then** 输出固定拒绝文本，并在非提交用审计信息中记录拒绝原因。

---

### User Story 4 - 审阅高风险答案与证据 (Priority: P2)

作为复核者，我希望看到每题的规范化意图、生成状态、风险提示和来源证据，以便优先人工检查复杂或不确定答案，并在导出前修正它们。

**Why this priority**: 正则、复杂逻辑、证书字段、外部资料和产品指纹容易产生隐蔽语义错误，需要可定位的人工复核入口。

**Independent Test**: 处理一组混合风险题目，确认所有高风险或低置信度答案均被标记，引用外部内容的题目带有可追溯来源，并可在保留题号的情况下修订最终答案。

**Acceptance Scenarios**:

1. **Given** 查询包含复杂布尔关系、正则、特殊转义或外部资料，**When** 生成完成，**Then** 系统将其标记为必须复核并说明具体风险点。
2. **Given** 题目明确要求读取某个外部来源，**When** 系统生成候选答案，**Then** 审阅记录包含实际使用的来源和提取事实；来源不可访问或证据不足时不得凭记忆生成。
3. **Given** 复核者修改某题答案，**When** 保存修订，**Then** 系统保留原题号、最新最终答案、校验结果和修订状态。
4. **Given** 任一题目尚未被人工确认，**When** 用户尝试导出正式答卷，**Then** 系统阻止导出；对于高风险题，只有来源证据和风险检查项均已核对后才能确认。
5. **Given** 题目指定的外部页面暂时不可访问，**When** 存在内容等价且可核验的官方替代页面、存档或用户材料，**Then** 复核者可用该材料补齐证据；否则该题保持阻塞且不得确认或导出。

---

### User Story 5 - 导出合规答卷 (Priority: P1)

作为参赛者，我希望在所有题目均有有效最终答案后，一次性导出符合比赛要求的 JSON 文件，确保可以直接上传且不会因格式、数量或附加内容被拒绝。

**Why this priority**: 即使单题答案正确，参赛包编号、题号集合或文件结构错误仍会导致整份答案无效。

**Independent Test**: 使用当前 100 题参赛包完成导出，核验文件可被标准 JSON 解析器读取，且包编号、题号集合、顺序、数量和查询字段均满足题目说明；再构造空答案和未复核高风险答案确认导出被阻止。

**Acceptance Scenarios**:

1. **Given** 所有题目均已有通过校验的最终答案，且必须复核项均已处理，**When** 用户导出答卷，**Then** 文件包含选手名称、原参赛包编号及与题目一一对应的答案数组。
2. **Given** 存在空答案、重复题号、未知题号、缺题或未完成的强制复核项，**When** 用户尝试导出，**Then** 系统拒绝导出并列出全部阻塞项。
3. **Given** 答卷满足导出条件，**When** 文件生成，**Then** 查询字段只含最终查询或固定拒绝文本，不含候选项、解释、Markdown、凭据或审计信息。

---

### User Story 6 - 使用本地 Web 界面完成作答 (Priority: P1)

作为时间紧迫的参赛者，我希望在第一版中通过本地 Web 界面完成题包导入、自动生成、进度查看、逐题复核、证据补齐和答卷导出，而不必依赖命令行完成日常操作。

**Why this priority**: 当前项目需要尽快用于实际作答；可视化的批量状态和逐题复核能降低操作成本及漏审风险。

**Independent Test**: 在全新本地环境中启动界面，仅通过浏览器完成当前 100 题题包的导入、生成、筛选、逐题确认、证据补齐和合规导出，并核验所得答卷与同一状态下的命令行导出一致。

**Acceptance Scenarios**:

1. **Given** 本地应用已启动且尚未导入题包，**When** 用户打开 Web 界面，**Then** 页面提供题目、参赛包信息和答案模板的导入入口，并显示每个文件的校验结果。
2. **Given** 一个有效题包已经导入，**When** 用户启动生成，**Then** 页面持续显示总体进度、各状态数量和逐题结果，单题失败不会隐藏其他题目的结果。
3. **Given** 存在待复核或证据阻塞题目，**When** 用户使用状态或风险筛选，**Then** 页面列出对应题目，并允许查看原题、规范化意图、候选答案、校验、风险和证据。
4. **Given** 用户在页面中修改答案、补充证据或核对风险项，**When** 保存操作，**Then** 页面显示重新校验后的最新状态，旧确认不再有效。
5. **Given** 全部导出门禁已满足，**When** 用户从页面导出答卷，**Then** 下载文件与相同工作区状态下的命令行导出内容一致；存在阻塞项时页面禁止导出并完整列出原因。

### Edge Cases

- 输入文件使用 UTF-8 BOM、不同换行格式或字段周围存在无意义空白。
- 题号顺序不同，但集合相同；导出必须恢复题目输入顺序。
- 自然语言中的“或”“且”“不要”“任意一项”“至少两项”等组合可能改变优先级。
- 相同关键词分别出现在标题、正文、响应头、Banner、证书或域名中，字段不得混用。
- 精确匹配、包含匹配、正则匹配和字段是否有值具有不同含义。
- IP 闭区间、CIDR、由单个 IP 推导的网段以及 IPv4/IPv6 排除条件需要边界验证。
- 国家、地区和城市名称使用中文、英文、简称或历史译名。
- 时间边界可能包含日期或秒级时间，并可能要求严格早于/晚于而不是包含边界。
- 查询素材包含中文弯引号、全角运算符、反斜杠、换行或需要原样保留的双引号。
- 外部网页无法访问、内容已变化或不能提供足够证据时，该题保持阻塞；仅在找到内容等价且可核验的官方替代页面、存档或用户材料后恢复处理。
- 生成结果语法有效但语义丢失部分限制；此类结果必须视为失败而非降级成功。
- 用户刷新、关闭或重新打开本地 Web 页面时，已保存的生成、验证、证据和复核进度不得丢失。
- 长时间生成过程中某一题失败时，页面仍需展示已完成题目和其余题目的继续处理状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 接收题目集合、参赛包信息和答案模板，并在处理前验证每个输入的格式和必需字段。
- **FR-002**: 系统 MUST 验证题目与模板的题号集合完全一致，且不存在缺失、重复或未知题号。
- **FR-003**: 系统 MUST 保留题目原始顺序、题号和参赛包编号，且不得改写原始输入文件。
- **FR-004**: 系统 MUST 为每道题产生且仅产生一个最终结果：一条 FOFA Query 或比赛规定的固定拒绝文本。
- **FR-005**: 系统 MUST 区分并保留字段范围、匹配模式、逻辑运算、否定、分组优先级、数据类型和边界条件。
- **FR-006**: 系统 MUST 支持当前题包出现的基础资产、网络位置、端口协议、产品分类、网页响应、证书、TLS 指纹、哈希、正则、时间和域名关系等意图类别。
- **FR-007**: 系统 MUST 对从其他搜索语法迁移的需求只生成可由 FOFA 等价表达的部分；任何必要语义无法保留时，必须拒绝转换，不得静默删减限制。
- **FR-008**: 系统 MUST 验证 IP、CIDR、IP 范围、端口、ASN、时间、哈希、证书序列号及其他有明确格式或范围的值。
- **FR-009**: 系统 MUST 验证最终查询的字段、运算符、括号、引号、转义、值类型和逻辑一致性。
- **FR-010**: 系统 MUST 检测明确矛盾、无效输入、主观标准、不可观察的运行时状态和 FOFA 无法表达的数据要求，并输出精确的固定拒绝文本。
- **FR-011**: 系统 MUST 将复杂分组、正则、特殊转义、外部资料、指纹推导、低置信度或自动校验无法充分证明的答案标记为强制人工复核。
- **FR-012**: 对要求外部资料的题目，系统 MUST 保存实际来源、提取事实和访问状态；原始页面不可访问时，只有内容等价且可核验的官方替代页面、存档或用户提供材料可作为替代证据，证据缺失时不得以模型记忆替代来源，也不得仅因访问失败输出固定拒绝文本。
- **FR-013**: 复核者 MUST 能按题号查看原题、规范化搜索意图、候选结果、验证结果、风险原因和证据，并确认或修改最终答案。
- **FR-014**: 系统 MUST 在每次修改后重新验证该题，并保留最终答案的复核状态和必要的审计信息。
- **FR-015**: 系统 MUST 在导出前验证所有题目均有非空最终答案，所有强制复核项均已处理，且答案数量与题目数量相同。
- **FR-016**: 系统 MUST 输出合法的 UTF-8 JSON，包含选手名称、原参赛包编号以及按输入顺序排列的题号和查询语句。
- **FR-017**: 导出文件 MUST NOT 包含候选答案、解释、Markdown、审计记录、账号、密钥或未经授权的数据。
- **FR-018**: 系统 MUST 为每批处理提供汇总，包括总题数、成功转换数、拒绝数、待复核数、校验失败数和阻塞导出的问题。
- **FR-019**: 用户 MUST 能在不调用在线查询服务或提供 FOFA 凭据的情况下完成导入、生成、本地校验、复核和导出流程。
- **FR-020**: 系统 MUST 支持重复运行同一题包，并在题目、规则、证据及用户确认均未变化时产生相同的规范化最终答案。
- **FR-021**: 准确率验收 MUST 将每题拆解为字段、匹配方式、值、逻辑关系、否定和边界等原子约束；只有全部适用约束均正确时该题才计为通过，且两名独立复核者的分歧必须在计分前形成一致结论。
- **FR-022**: 正式答卷中的每道题 MUST 在导出前获得逐题人工确认；高风险题只有在复核者核对来源证据和全部风险检查项后才允许标记为已确认。
- **FR-023**: 外部证据缺失的题目 MUST 保持阻塞状态并阻止正式答卷导出，直至复核者确认原始来源或符合 FR-012 的替代证据已经补齐。
- **FR-024**: 第一版 MUST 提供仅在用户本地运行的 Web UI，并覆盖题包导入、答案生成、状态汇总、逐题复核、证据管理和答卷导出完整流程。
- **FR-025**: Web UI MUST 提供按处理状态、风险级别、证据状态、验证结果和题号筛选与定位题目的能力。
- **FR-026**: Web UI MUST 在批量生成期间显示总数、已完成数、处理中数量、失败数和阻塞数，且单题失败不得清除其他题目的结果。
- **FR-027**: Web UI 与命令行入口 MUST 使用同一套工作区状态、验证规则、复核门禁和导出逻辑；不得形成两套互相不一致的业务行为。
- **FR-028**: 用户通过 Web UI 修改候选答案、证据或风险检查项后，系统 MUST 保存进度、重新验证受影响题目并使旧确认失效。
- **FR-029**: Web UI MUST 默认只接受本机访问，不提供多用户账号、远程公开访问或绕过导出门禁的强制操作。

### Scope Boundaries

**In scope**:

- 读取比赛题包并验证题目、模板和包编号的一致性。
- 把自然语言搜索意图转换为一条最终 FOFA Query，或作出规定格式的安全拒绝。
- 对候选答案进行语法、类型、边界、逻辑和完整性校验。
- 为高风险答案提供逐题人工复核与修订能力。
- 生成符合比赛上传结构的本地答案文件。
- 通过本地 Web UI 完成导入、生成、状态跟踪、复核、证据补齐和导出，并保留等价的命令行入口。

**Out of scope**:

- 自动登录比赛网站、自动上传答卷、自动读取排行榜或执行任何部署发布操作。
- 未经用户明确授权使用 FOFA 账号、付费查询额度或批量执行生成的查询。
- 主动扫描互联网、绕过访问控制或收集题目所需范围之外的资产数据。
- 将第一版扩展为公开部署或多用户平台、通用聊天机器人或完整资产管理系统。
- 保证第三方搜索索引本身的数据完整性、时效性或排名结果。

### Key Entities *(include if feature involves data)*

- **参赛包**: 一次比赛作答的边界，包含唯一包编号、发放信息、题目集合和答案模板。
- **题目**: 由唯一题号和自然语言搜索需求组成的单个转换任务，保持输入顺序。
- **规范化意图**: 对题目要求的结构化语义描述，包括字段、匹配方式、值、逻辑组合、边界和不可丢失约束。
- **候选答案**: 尚未完成全部校验与复核的查询或拒绝判断。
- **验证结果**: 对输入合法性、查询结构、语义完整性和逻辑一致性的逐项判定及错误信息。
- **证据记录**: 支持字段选择、外部事实或不可转换判断的来源、提取事实和访问状态。
- **复核记录**: 某题的风险级别、复核要求、修改状态与最终确认状态。
- **最终答案**: 与一个题号唯一对应、已通过必要校验和复核的查询语句或固定拒绝文本。
- **答卷**: 包含选手名称、参赛包编号和完整最终答案集合的上传文件。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对当前 100 题参赛包，系统能在一次运行中生成 100 条且仅 100 条结果，题号覆盖率、唯一性和顺序一致性均为 100%。
- **SC-002**: 对项目维护的已人工审阅基准集，至少 95% 的可转换题通过语义全通过验收；每题的字段、匹配方式、值、逻辑关系、否定和边界等全部适用原子约束必须正确，遗漏或错误任一项即整题失败，且每题由两名独立复核者判定并在分歧时形成一致结论。
- **SC-003**: 对基准集中的非法值、明确矛盾、主观条件和不可观察运行时数据，固定拒绝判断准确率达到 100%。
- **SC-004**: 所有生成结果均通过结构检查，括号、引号、转义和题目要求的值不存在未检测出的破损；发现破损时导出成功率为 0%。
- **SC-005**: 100% 的外部资料题在允许确认最终答案前具备可追溯来源和提取事实；原始来源不可访问且没有合格替代证据的题目全部保持阻塞，且不会仅因访问失败被标记为不可转换。
- **SC-006**: 100% 的题目在导出前具有逐题人工确认状态，且 100% 的高风险题具有来源证据和风险检查项已核对记录；缺少任一记录都会阻止导出。
- **SC-007**: 对一个已准备好的 100 题题包，用户可在 10 分钟内完成导入、自动生成和获得按风险排序的复核清单，不含人工阅读与外部资料查证时间。
- **SC-008**: 首次使用的参赛者能够依据错误提示，在 2 分钟内定位任一缺题、重复题号、空答案或未知题号问题。
- **SC-009**: 最终答卷可被标准 JSON 解析器读取，文件结构、包编号、题号集合、答案数量和禁止附加内容的合规率均为 100%。
- **SC-010**: 相同输入与已确认资料连续运行三次，规范化最终答案逐项一致率为 100%。
- **SC-011**: 用户无需使用命令行即可在本地 Web UI 中完成 100% 的核心工作流：导入、生成、状态查看、逐题确认、证据补齐和答卷导出。
- **SC-012**: 对同一工作区状态，Web UI 与命令行连续三次导出的规范化答卷内容一致率为 100%。
- **SC-013**: 在 100 题规模下，页面筛选或切换到任一题目的操作有 95% 在 1 秒内呈现结果；生成任务运行期间页面每 2 秒内更新一次可见进度。

## Assumptions

- 第一版面向单个本地参赛者或复核者，通过本地 Web UI 和等价命令行入口操作，不需要账号体系、多人协作、权限分级或公开部署。
- “题目”目录中的说明是答卷结构和固定拒绝文本的权威来源；FOFA 字段与运算语义以已核实的官方资料和项目证据为准。
- 当前题包的 100 道题代表第一版必须覆盖的意图范围，但系统结构应允许日后增加新的题型和规则。
- 生成查询不等于执行查询；第一版的核心验收不依赖 FOFA 凭据或在线搜索额度。
- 用户负责提供最终选手名称，并对正式提交承担最终确认责任。
- 访问公开外部资料可能需要网络；无法访问时系统保持阻塞状态，不编造来源内容，并仅接受内容等价且可核验的官方替代页面、存档或用户提供材料作为替代证据。
- 项目仅处理用户有权使用的竞赛材料和公开资料，不以生成结果主动探测或攻击互联网资产。
